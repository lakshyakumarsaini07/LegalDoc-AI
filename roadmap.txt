## Full Pipeline for a Production-Grade RAG Chatbot

You already have the core pieces for a legal RAG system. The production pipeline should look like this:

1. **Data Ingestion**
   - Raw inputs: json metadata + pdfs documents
   - Output: cleaned JSON/HTML data and extracted PDF text

2. **Preprocessing**
   - Clean HTML/text
   - Extract metadata fields
   - Normalize and unify document IDs
   - Output: parquet or structured files for downstream use

3. **Chunking**
   - Split long documents into searchable chunks
   - Keep metadata per chunk (`doc_id`, `chunk_id`, court, judge, year)
   - Output: chunk parquet / chunk dataset

4. **Embedding & Vector Store**
   - Convert chunks into vectors
   - Store vectors in FAISS (or another vector DB)
   - Save metadata mapping for each vector

5. **Retrieval + RAG**
   - Accept user query
   - Retrieve top relevant chunks from vector store
   - Build prompt/context from retrieved chunks
   - Call LLM to answer/chat/summarize/generate

6. **UI / Chatbot**
   - Web or API interface to receive user questions
   - Show responses, sources, citations, and follow-up capability

7. **Production Hardening**
   - Deployment
   - Monitoring and logging
   - Error handling
   - Model configuration / rate limiting
   - Data refresh and reindexing

## Phase-by-Phase Plan

### Phase 1: Data Pipeline
Build or refine these services:
- `PDF Extraction Service`
  - Convert `data/pdfs/*.pdf` → pdf_text_data
- `Metadata Processing Service`
  - Convert `data/json/*.json` → processed_data
- `Chunking Service`
  - Convert extracted text + metadata → chunks_data

### Phase 2: Embeddings & Indexing
Build:
- `Embedding Service`
  - Use a stable model like `all-MiniLM-L6-v2`
- `Vector Store Service`
  - Create / update FAISS index
- `Index Refresh Service`
  - Rebuild index when new docs arrive

### Phase 3: Retrieval + RAG Orchestration
Build:
- `Retrieval Service`
  - Query vector store and return top chunks
- `Prompt Assembly Service`
  - Format retrieved chunks plus system prompt for the LLM
- `LLM Inference Service`
  - Call OpenAI / HuggingFace / local model
- `Answer Service`
  - Post-process output, add citations and safety filters

### Phase 4: Chat UI / API
Build:
- `Chat API`
  - REST or FastAPI endpoint
- `Frontend UI`
  - Streamlit / Gradio or simple web page
- `Conversation Manager`
  - Maintain chat state, follow-ups, memory

### Phase 5: Production Grade
Build:
- `Deployment Service`
  - Docker / cloud deployment
- `Monitoring Service`
  - Logs, errors, latency, usage
- `Security Service`
  - Auth, API keys
- `Data Refresh Service`
  - Scheduled re-indexing and incremental ingestion
- `Evaluation Service`
  - Accuracy checks, hallucination detection, scoring
